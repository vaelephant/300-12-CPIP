## 3. 端到端演示

后端运行后：

```bash
cd back
python3 scripts/demo_e2e.py
```

脚本执行：登录 → 发布路径 → UNKNOWN 阻断入径 → 补充快照 → 入径 → 实例 → 计划生成/审核/激活 → 任务状态机 → 变异重规划 → 随访人工升级 → 结局 → 聚合指标 → 审计查询。

期望最后输出：

```text
E2E demo passed (synthetic data; clinical_use=false).
```

## 4. SQLite 备份与恢复

创建并校验在线备份：

```bash
cd back
python3 scripts/backup_sqlite.py
# backup ok: backups/hcc-cip-<timestamp>.db · integrity=ok · users=8
```

恢复（会先自动创建 `pre-restore` 安全副本）：

```bash
python3 scripts/restore_sqlite.py backups/hcc-cip-<timestamp>.db --yes
```

本地演练要求：

- 每次演示前备份；
- 恢复后重新运行 `pytest` 与 `demo_e2e.py`；
- 生产环境必须使用 `pg_dump/pg_restore`、独立备份存储、加密和定期恢复演练，不能按本脚本上线。

## 6. 安全与边界

- 管理员、医务处、院级管理默认无患者病历访问权限；临床角色仅本科室。
- 拒绝访问也写审计；错误信封带 `request_id`。
- 未登录、跨科室、无病历权限管理员、越权对象访问均服务端拒绝。
- UNKNOWN 不会自动通过；发布路径需审批；计划激活前重新检查安全规则。
- 外部服务不可用必须返回真实状态，**不得伪造成功**。
- 当前 JWT 为本地开发密钥，不可用于真实环境。
- 所有患者、指标、模型结果均为合成演示数据，`clinical_use=false`。
