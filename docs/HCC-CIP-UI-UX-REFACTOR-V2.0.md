# HCC-CIP UI / UX 第二轮改造需求（Clinical Workspace V2.0）

状态：待研发实施与产品验收。范围：前端 UI、交互、信息架构与可视化；不修改临床业务规则、后端接口或数据库。本文为新增实施需求，保留既有设计系统文档作为历史基线；冲突项由产品负责人确认后统一。

## 1. 目标与现状
从通用后台管理系统升级为临床智能工作空间。优先解决患者状态、动态路径、决策证据分散的问题，而非仅换皮。源码审计发现 globals.css 的紫蓝品牌色、历史 DESIGN.md 与新版规范存在差异；工作台多区块等权、患者详情大量 9–12px 字号、路径节点 200px 宽却承载多项元数据。ECharts 与 Recharts 并存，实验 kit 独立。以上为源码审计结论，尚未进行浏览器视觉验收。
参考 docs/HCC-CIP-DESIGN-SYSTEM-V1.0.md、docs/V1.0-DESIGN-SYSTEM-STATUS.md、front/DESIGN.md 和 front/docs/preview/design-system-v1/。开发前重新运行当前 main，记录 commit、浏览器、视口、数据模式，截图留档。

## 2. 视觉方向（建议作为本轮统一基线）
Apple 式克制排版与 Linear 式清晰工作空间，医疗专业性优先，不照搬其产品。白色主工作面、浅灰辅助区、深灰正文，红色仅用于真实风险或阻断；当前节点使用深色轮廓与文字标识，正常、警告、未知各有明确文字和图标，不能只靠颜色。
- 建议 token：canvas #F6F7F8、surface #FFFFFF、ink #17181A、secondary #50545A、muted #62676E、line #E4E6E9、risk #B84242。语义色须通过对比度验证，品牌标识与风险不能混淆。
- 页面标题 24px/32px，区块标题 16px/24px，正文 14px/22px，辅助 12px/18px；表格可用 13px，临床关键内容不得缩成 9–10px。数字使用等宽数字而非全页等宽字体。
- 间距 4/8/12/16/24/32px；普通区块 16–24px 内边距；圆角 6–8px；减少边框、卡片嵌套和阴影。弹层可有轻阴影；禁止渐变、大面积彩色卡片、装饰性发光、无意义动画。
- 统一按钮、表格、标签、输入、空态、加载态、错误态、抽屉、图表和节点组件。每个页面一个明确主操作，危险操作保留确认。
- 中文优先，英文仅保留必要术语；模块编号、接口地址、内部 ID 移到技术详情，不删除必要的演示数据声明。

## 3. P0：全局基础与患者360样板
### UI-01 全局框架
文件：front/src/styles/globals.css、components/app/app-shell.tsx、components/app/page-header.tsx、components/app/topbar.tsx、components/app-sidebar.tsx、components/nav-main.tsx（后续路径均相对 front/src）。
保留现有路由、RBAC、导航收起和快捷键。建议侧栏 208–224px，收起 48–56px，顶栏 52–56px；减少重复面包屑、标题与页脚。全屏工作区允许独立滚动，不产生整页横向滚动。工作空间切换若只改变显示名称而不改变真实数据上下文，应隐藏无效选项或明确标注演示，不得误导组织权限。统一历史规范与运行时 token；不引入第二套组件库。

### UI-02 患者360临床工作空间
文件：pages/patients/detail.tsx、pages/patients/detail-server.tsx，以及相关患者路径、地图页面。复用共同展示组件，保留两种数据适配，不复制两套视觉。
顶部固定患者身份摘要：姓名、病历标识、年龄/性别（如有）、诊断、当前阶段、关键风险、数据时间与来源。下方三栏：
- 左栏 240–280px：患者状态、分期、肝功能、ECOG、关键检验、缺失字段；异常值展示单位、参考范围和采集时间（仅在来源提供时）。
- 中央弹性区：动态临床路径为主视图，阶段轨道、当前节点、已完成与未执行节点、任务及变异；时间轴与检验趋势可切换，保留患者上下文。
- 右栏 300–340px：当前任务、风险/变异、循证依据、待审核计划及已有智能建议。点击路径节点联动检查器，展示责任角色、时限、证据、状态原因、操作权限。不存在的能力显示不可用，不制造建议。
1440×900 下优先保证中央可用宽度，必要时右栏折叠为抽屉；1920×1080 三栏完整展示；1280px 以下逐步折叠侧栏与检查器，窄屏采用单栏/抽屉。所有关键内容仍可访问。保留原有任务、审核、随访、回放、导出等功能入口；不得以美化为由删除。
验收：首屏可识别患者、当前阶段、待办及异常；从异常定位相关节点与证据不超过三次操作（以已有数据和权限为前提）；切换患者不残留上一个患者状态；无权限、缺失、加载、错误、空数据均正确展示。

### UI-03 动态路径可视化
文件：visualization/pathway/LivePathwayNodeCard.tsx、LivePathwayGraph.tsx 及相关路径画布。
节点默认仅显示任务名称、状态、必要的异常标识；角色、时限、证据数量、内部 ID 等放入检查器或展开详情。保留必做标识但不用风险红表示普通必做。采用阶段分组、正交或简洁曲线连线、统一节点尺寸与间距；主路径优先，分支条件可读，未选分支弱化但不隐藏关键约束。不得把条件未知画成已通过。
保留 React Flow 的缩放、平移、适应画布、选择；提供回到当前节点、阶段定位和状态图例。适应画布不能导致文字不可读，允许缩略概览与局部阅读。节点点击联动右栏；选中与执行中状态必须区分。只读视图不得变成可编辑正式路径；编辑器原有操作保留。
验收：正常、执行中、变异、阻塞、UNKNOWN、未选分支均有文字和非颜色标识；无节点重叠、标签截断或连线遮挡关键文字；用现有真实结构及长名称、并行分支样例测试。

## 4. P1：工作台与统一可视化
### UI-04 工作台
文件 pages/dashboard/index.tsx。改为任务驱动：顶部精简指标条，中部以今日待办及重点风险患者为主，辅助区展示阶段、变异和审核。按权限显示，排序与筛选可解释；指标可下钻到对应列表。不得使用硬编码患者链接代表全局统计，演示数据明确标识。保留所有已有入口。
### UI-05 图表统一
文件 components/charts/chart-theme.ts、visualization/core/theme.ts。ECharts 作为新图表默认实现，已有 Recharts 逐步迁移，先盘点调用，不直接卸载。统一轴、单位、图例、tooltip、时间格式、字体和语义色；普通趋势使用中性色，异常用红色与文字。检验趋势、时间轴、甘特、Sankey、热图与预测图遵循同一主题；不为美观平滑或插补临床数据造成误读。预测和观测明确区分，模拟曲线标注非临床使用，缺失不当作零。图表支持 resize、销毁、空态和键盘可访问的关键数据替代视图。
### UI-06 设计实验区
front/src/dev/desgin/ 保留为隔离实验区（现有拼写），正式页面不得依赖实验 token。确认无引用后再决定迁移或重命名。同步更新设计规范与状态文档，明确唯一运行时 token 来源。

## 5. 实施边界
保留 React/Vite/TypeScript、Tailwind、shadcn、React Flow 与现有服务层。不得改动临床路径规则、状态机、权限判断、审核、审计、数据契约、后端 API 或数据库。不得绕过审批、用 mock 替代 server 数据、把 UNKNOWN 显示为正常、将模拟预测包装成真实临床结果。不得为了截图写死数据或隐藏错误。若发现业务缺陷单独记录，不在视觉改造中擅自修复。无新增依赖必要性不引入依赖。

## 6. 建议排期（单名前端约 10 个工作日，实际以评审为准）
D1 基线截图与组件盘点；D2 token/排版；D3 shell/header；D4–5 患者360共用布局及两种数据模式；D6–7 动态路径与检查器联动；D8 工作台；D9 图表主题与状态；D10 回归、截图、产品评审。P0 样板未获批准前不全面铺开 P1。每阶段独立 commit/PR，便于回滚。

- [ ] 提交改造前后截图：1440×900、1920×1080，另测 1280×800 和窄屏；同一合成患者、角色、数据状态、浏览器与缩放比例对照。截图不含真实患者信息。

完成定义：不是换色或生成静态原型，而是在现有工程中形成可运行、数据驱动、可操作、视觉统一的临床工作空间，且原有临床安全与业务行为保持不变。
