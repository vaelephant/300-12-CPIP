## 2. 总体决策

### 2.1 单病种边界

- `Patient.diagnosis_code` 固定 `C22.0`（肝细胞癌）；Schema 使用 `const`，其他肝癌亚型（如肝内胆管癌）必须新建病种契约，不能复用 HCC 规则。
- 消融、TACE、系统治疗、转化治疗属于 HCC 的不同治疗路径；**不扩展其他病种**。
- 首个验收闭环只覆盖肝切除 + 随访；其他治疗路径的路径模板可存在，但不在本次 P0 验收断言中。

### 2.2 标识与时间

- 业务 ID 使用稳定字符串（生产建议 UUIDv7/ULID；本契约不限定具体生成算法，示例使用可读 ID）。
- 所有时间使用 RFC 3339 带时区时间戳（示例为 `+08:00`），服务端统一存 UTC。
- 区分 `occurred_at`（临床发生时间）与 `recorded_at`（录入时间）；事件导入允许补录，但必须保留两者。
- 观测单位使用 UCUM/标准符号字符串；缺失单位不得默认为“无单位即正常”。
- 金额、剂量等如需新增字段，必须配套单位与精度规则，不以浮点默认值表示未知。

### 2.3 三值逻辑（强制）

| 场景 | 结果 |
| --- | --- |
| AND：任一 FALSE | FALSE |
| AND：无 FALSE、至少一个 UNKNOWN | UNKNOWN |
| OR：任一 TRUE | TRUE |
| OR：无 TRUE、至少一个 UNKNOWN | UNKNOWN |
| NOT UNKNOWN | UNKNOWN |
| 未注册规则 / 单位不匹配 / 观测过期 / 执行失败 | **UNKNOWN 或显式错误；不得默认 TRUE** |

入径决策：

- `admission_tri_state = UNKNOWN` 或 `exclusion_tri_state = UNKNOWN` → `PENDING_SUPPLEMENT`，`auto_enroll_allowed = false`。
- `exclusion_tri_state = TRUE` → `NOT_ELIGIBLE`。
- 仅当 admission TRUE、exclusion FALSE、完整性满足（completeness TRUE）时才允许 `ELIGIBLE`。
- “医生知晓缺失”不是“符合条件”；例外需独立授权、理由与审核记录（契约预留审批/审计，不在本批实现）。

### 2.4 状态机（服务端唯一事实源）

**Plan**  
`DRAFT → PENDING_APPROVAL → APPROVED → ACTIVE → SUPERSEDED / COMPLETED`  
- 拒绝后生成新草稿，原计划保留。
- 激活时必须重新检查最新快照、规则版本、关键安全条件。
- 已 ACTIVE 计划不可被覆盖；重规划产生新版本。

**Task**  
`PENDING → READY → IN_PROGRESS → COMPLETED`，另有 `BLOCKED / SKIPPED / CANCELLED`。  
- 依赖未完成不得进入 READY/IN_PROGRESS（服务端校验）。
- 超时是独立标记，不改变执行状态。
- 完成必须带结果摘要与来源；`expected_version` 用于乐观并发。

**Variation**  
`OPEN → ASSESSING → REPLAN_PENDING → RESOLVED / CLOSED`。  
- 事件触发或人工登记；重规划不得删除已完成任务；保留原计划与差异。

**Follow-up**  
`WAITING_CONTACT → CONTACTING → COLLECTED → PENDING_REVIEW → PENDING_ACTION → CLOSED`，另有 `DECLINED / LOST_TO_FOLLOWUP / RESCHEDULED`。  
- 失败可重试/改约/失访，**不得自动标记完成**。
- 危险信号必须进入人工队列，记录通知、签收、处置、关闭。
- LLM 仅做受约束追问与抽取；患者原话与结构化结果分存，关键字段人工确认。

### 2.5 版本、幂等与并发

- PathwayVersion 发布后不可变；`content_hash` 为冻结图哈希。
- 所有写操作校验对象级权限；版本冲突返回 `409`；入径、计划激活、事件导入、任务转换支持 `Idempotency-Key`（契约中为 `idempotency_key`）。
- 审批记录、历史计划、审计事件只追加，不覆盖。
- 外部系统不可用时返回真实状态与错误；**不伪造同步成功**。

### 2.6 权限与审计

- 登录/授权以服务端为准；前端 `session-store` 不作为授权依据。
- 角色与数据范围：本人 / 科室 / 全院聚合 / 全院不含病历（系统管理员默认无病历访问）。
- 对象级授权：跨科室、无病历权限管理员、未登录均拒绝；拒绝也写审计。
- 审计不含明文密钥、完整身份证号、完整联系方式或真实病历；`ip_masked` 仅保留脱敏值。
- 每个错误响应带 `request_id`，便于审计关联。

## 3. 实体覆盖

| Schema | 关键约束 |

| `variation` | 七类变异、严重度、影响节点、处理状态、证据 |

## 4. 合成验收病例 `HCC-ACC-001`

患者：**陈志远**（HCC，C22.0，Ⅰb，Child-Pugh A，单发 32 mm S6，无血管侵犯/肝外转移，AFP 86.4，HBV+），对应现有前端演示病例 `HCC-DEMO-001`。

关键断言：

| 断言 | 期望 |
| --- | --- |
| 初次评估 | NRS 2002 为 UNKNOWN → `PENDING_SUPPLEMENT`；`auto_enroll_allowed=false` |
| 补充后评估 | 新快照 `SNAP-HCC-002`，NRS 2 分 → `ELIGIBLE` |
| 入径 | 仅 `ELIGIBLE` 且医生确认后可创建实例 |
| 计划 | 必须审核后激活；`PLAN-HCC-P1` ACTIVE，重规划保留历史 |
| 任务 | 依赖未完成的 READY 不得存在；超时独立标记 |
| 变异 | 术后体温 37.6°C 登记为临床变异，不自动修改计划 |
| 随访 | AFP 46.8、乏力 → HIGH 风险，人工升级，通知/签收时间完整，不自动关闭 |
| 结局 | 关联患者/实例/治疗与观察时间；评价标准显式 |
| 审计 | 系统管理员访问患者被 DENIED 且有审计事件 |
| 数据边界 | `synthetic=true`，`clinical_use=false` |

## 6. 待临床/团队确认

1. **分期体系版本**：CNLC 2024 与 BCLC 2022 的字段映射、是否同一快照保存多体系。
2. **Child-Pugh/ALBI 版本与公式**：评分来源与单位；异常值时的人工复核策略。
3. **规则版本命名**：`HCC-RULES-0.6.0` 为示例；需与 KEE 规则仓库对齐。
4. **随访危险信号阈值**：AFP 上升幅度、体温、症状组合需临床专家审阅；当前仅验证流程可表达。
5. **对象级授权模型**：科室 / 病区 / 医疗组 / 患者归属的最终口径。
6. **数据库选择**：PostgreSQL 生产 + 本地是否允许 SQLite；迁移策略需在 T03 确认。
7. **外部适配器契约**：KEE/MWM 的真实 API 尚未核实；当前仅定义 HCC-CIP 侧输入输出与降级行为。
