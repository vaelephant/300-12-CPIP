> 所有数据为合成数据，`clinical_use=false`；规则仍需临床专家确认。

## 已完成

### T21 时点快照与激活校验（完成）

- `RuleContext` 只使用快照 `as_of` 时点内、`observation_refs` 引用、属于该患者的观测
- 未来观测不会泄漏进规则
- 统一 latest snapshot 排序：`as_of DESC, created_at DESC`
- 计划激活时比较最新快照；旧计划返回 `409 PLAN_REASSESSMENT_REQUIRED`

### T23 三值/单位/缺失边界（完成）

- AND/OR/NOT 真值表测试
- 缺失布尔字段不再被 `is True` 反推为阴性
- 观测单位白名单：单位不匹配 → UNKNOWN
- 未引用观测、未来观测不参与计算
- 新增 `tests/test_rules_hardening.py`

### T24 随访风险闭环（完成基础版本）

- 新增 `followup_alerts`、`followup_contacts` 独立表
- 预警状态：`NOTIFICATION_PENDING → NOTIFIED → ACKNOWLEDGED → RESOLVED → CLOSED`
- 新增：
  - `GET /followup-alerts`
  - `POST /followup-alerts/{id}/notify`
  - `POST /followup-alerts/{id}/acknowledge`
  - `POST /followup-alerts/{id}/resolve`
  - `POST /followup-alerts/{id}/close`
- 不再伪造 `notified_at/acknowledged_at`；未通知不能签收，未处置不能关闭
- 联系记录独立存储；未人工确认的抽取不会写入结构化记录
- 随访关闭要求所有预警已关闭

### T20 条件图执行（部分完成）

- 新增 `services/graph_execution.py`：从 START 选择执行子图，支持条件边 TRUE/FALSE/UNKNOWN、显式默认分支、并行 fan-out，并输出 `execution_trace`
- UNKNOWN 条件阻断下游，不默认 FALSE
- 计划保存 `graph_content_hash`、`execution_trace_json`、`execution_blocked`、`execution_fingerprint`
- 审批绑定 `subject_fingerprint`；激活时重算指纹，trace 被篡改返回 `409 PLAN_FINGERPRINT_MISMATCH`
- 计划提交/激活在 `execution_blocked=true` 时返回 `409 EXECUTION_BLOCKED`
- 计划任务只生成选中分支节点；未选分支不生成任务
- 显式 `gateway_type`（XOR/AND）与 `join_policy`（首期仅 ALL_ACTIVE）校验
- AND 网关禁止条件边，AND 至少两条出边
- 审批指纹绑定：`execution_fingerprint` + Approval `subject_fingerprint`，trace 篡改返回 `PLAN_FINGERPRINT_MISMATCH`
- 未支持 OR/ANY join、复杂互斥证明；独立待补充事件仍为后续

### T22 事件驱动重评/重规划（完成基础版本）

- `clinical-events/import` 对 `PatientStateUpdated` / `ObservationImported` / `VariationDetected` 等事件自动生成 `reassessments`，同事件幂等
- 新增 `GET /reassessments`、`POST /reassessments/{id}/dismiss`、`POST /reassessments/{id}/replan`
- 重规划生成新的 DRAFT 计划与执行 trace，原 ACTIVE 计划保持不变
- 已完成任务按 node_key 继承，旧计划不删除
- 新计划激活后旧计划任务不可再执行（测试覆盖）
- 未完成：独立 outbox/事件表、受影响实例依赖索引、旧任务冻结状态、拒绝新计划后的回滚展示

### T27 Demo / Server 隔离（完成基础版本）

- 统一 `VITE_DATA_MODE=demo|server`（兼容旧 `VITE_HCC_API_MODE`）
- Server 登录后调用 `/me`，身份以服务端为准；失败不回退本地 `loginAs`
- 后端 `401`：清理令牌、会话和 React Query 缓存，回到登录页
- `403`：展示无权限，不展示本地 mock 数据
- 退出登录和身份失效都会清空后端查询缓存
- 后端用户响应补充 `employee_no`
- 仍未完成：生产 HttpOnly/Secure Cookie 会话方案复核；令牌当前仍在 localStorage

### T26 后端页面迁移（部分完成）

- 变异管理：读取 `/variations`，支持处置/关闭与缓存失效
- 随访管理：读取 `/followups`，支持关闭并展示预警拦截错误
- 运营分析：读取 `/analytics/summary`，仅展示后端聚合指标和定义
- 仍未完成：路径设计器、审批中心、患者地图/回放、知识库、模拟、驾驶舱、设置页的真实写入迁移

### T29 生产配置与安全（部分完成）

- 非 dev/test 启动时拒绝默认 JWT 密钥、SQLite、auto-create tables、通配 CORS
- 登录失败限流：按工号 + IP，默认 5 次/300 秒，返回 `429 RATE_LIMITED`
- seed 在非 dev/test 环境默认拒绝演示账号，需显式 `--allow-demo`
- 仍未完成：TLS/反向代理、会话刷新/吊销、MFA、依赖审查、PostgreSQL 生产验证

### T25 原子并发与审计（基础完成）

- 任务状态转换改为 `UPDATE ... WHERE id AND row_version AND expected_status`
- 影响行数不为 1 → `409 VERSION_CONFLICT`
- 任务转换、计划激活的成功审计与业务写在同一事务提交
- 每实例唯一 ACTIVE 计划：partial unique index `uq_plans_one_active_per_instance`；并发激活冲突返回 409
- 仍未完成：计划版本号并发分配、完整 outbox/外部通知重试、全部路由成功审计原子化、PostgreSQL 并发测试
